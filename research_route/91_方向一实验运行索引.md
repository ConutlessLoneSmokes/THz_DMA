## 2. 当前证据链

1. Stage 0 至 Stage 1-A2 证明真实 DMA 频率响应能够提供有用的跨频结构，并且在输出 SNR、近场模型和固定导频 RE 口径下仍有继续研究的理由。
2. Stage 1-B 至 Stage 1-D 证明简单 Grid OMP 存在算法地板，离网格方法在旧一维场景中有效，而直接搬运低秩预处理不能代表原论文张量机制。
3. Stage 2-0 已建立统一的 8×160 二维接收 DMA、三径太赫兹信道与等 128 RE 的 F1/F2 协议，后续方法应适配同一平台。
4. Stage 2-A 尚未形成可用的正式传统方法基准。D-024 的 100 场景条件诊断显示，局部细采样可使 F2 的导频、全带和未观测域一致，Yang 在 55/65 dB 的全带 NMSE 为 −23.821/−33.734 dB，说明旧 F2 距离伪峰由粗网格基失配触发。F1 Yang 虽有 −17.420/−28.289 dB 的逐样本中位数，但线性均值转 dB 仅为 −6.691/−6.754 dB，达标率为 63%/67%；稳定长尾来自局部窗内角度竞争峰。

因此当前不能把“Stage 2 平台通过”或“F2 条件诊断通过”解释成“Stage 2-A 全部估计通过”，也不能直接开始固定正式配置的方法排名或学习模型。最新解释以 [[19_方向一Stage2A固定扇区诊断与下一验证]] 第 7–13 节为准。

四轮固定扇区后续诊断和 D-024 条件 Monte Carlo 均已完成。下一步不扩大到全扇区密网格；应先分解 F1 单径/三径的真值峰与错误角度峰，再决定状态、少量配置或任务目标是否需要改变。该下一实验尚未确认。

## 3. 保留文件的使用方式

- 每个 `runs/<run_id>/` 是主证据目录，包含解析配置、源码哈希、随机种子、逐样本数据和运行时汇总；不得覆盖或事后改写。
- `results/direction1_stage*/` 只保存正式或当前诊断运行的紧凑副本，供快速读取。
- `configs/` 只保留正式配置及下一步仍需使用的固定扇区诊断配置。
- `scripts/run_direction1_stage*.py` 是运行入口；`scripts/analyze_direction1_stage*.py` 是可用阶段的独立重分析和绘图入口。
- `src/thz_dma/` 保存公共物理、观测、估计和评价实现。

2026-09-10 已将临时 smoke 配置与结果、两个被 Stage 0 v3 取代的中间运行、`tests/` 和解释器缓存移入 Windows 回收站。历史运行中的 `code_manifest.json` 仍会记录当时存在的测试文件及其哈希；这是不可变的运行溯源，不代表这些测试文件仍存在。
