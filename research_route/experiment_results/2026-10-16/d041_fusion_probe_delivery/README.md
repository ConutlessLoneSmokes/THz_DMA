# 前两步实施与小样本核验

日期：2026-10-16。用户授权先验/引导/噪声诊断和无需新训练的融合原型。实现及小检查已完成，较大验证尚未启动，完整命令见[运行指南](../../../../docs/D041_FUSION_RUN.md)。原D-041数据、模型、运行源码、测试选择及报告保留。

## 1. 实施范围与验收

复用既有无吸收宽带数据及Clean DDPM。五个代表算子为8192 RE的64×128、4096 RE的64×64/128×32/128×32交错、128 RE的16×8。每组保留两个无噪声数值似然方差，前两组另加训练集标定的20 dB观测，共12个条件。

新增独立VP条件均值融合分支A1，标量实协方差来自冻结去噪器的训练误差。逐频SVD实现正确处理复方差与实方差的2倍换算；不叠加原似然引导。没有协方差网络训练，也不声称复现完整Peng算法、精确后验采样或确定性轨迹全局MMSE。

- 84项检查通过，其中13项为新增融合检查；覆盖一般高斯条件均值/协方差、紧凑观测SVD与独立实矩阵求解、方差换算、行/零空间、初态配对、关闭融合退化到原无引导递推、最终融合均值、训练专属标定与验证选参。一般高斯局部控制最大相对误差2.37e−13。
- CPU小链路复用旧8步小模型；真实GPU小链路使用原100步正式模型和8×160阵列。各完成标定、选参和筛选三个阶段，各84条最终指标，无非有限案例；分别540/6060条反向状态和180/420条去噪均值诊断。
- 两套小链路均只用2个训练场景标定标量方差，验证场景0选参、场景1冻结筛选。小检查只比较引导4/16，正式才运行全部6个值；两套小检查续跑均核对后跳过三个已完成阶段。
- 真实GPU的五算子×两数值方差、固定引导4的十个原DDPM端点，与旧预算验证场景0逐项一致，CSI NMSE差为0。硬件状态/选频哈希、秩及全2048训练场景的参考功率亦一致。
- 检查缺失父运行、改动标定文件和改动源码的拒绝行为。缺失前置记录不创建筛选运行。拒绝检查只改临时副本，不修改原运行。
- 182个实施前源码/配置/输出文件哈希保持；两个历史清单的21607和35681个文件，共57288个不同文件，大小与SHA256保持。

机器核验见[verification.json](verification.json)，可复核程序见[verify_delivery.py](verify_delivery.py)，实施前保护基准见[protected_files.json](protected_files.json)。源代码、逐阶段环境和输入依赖已随每个新运行保存。

## 2. 真实模型的单场景信号

下表只取**验证场景1**，原方法的引导由场景0在4/16中选定，均选4。无噪声按两数值方差较差值报告。A1的标定只用2个训练场景，不能据此下正式性能结论。

| 场景/配置 | 原DDPM NMSE，dB | A1 NMSE，dB | 读法 |
|---|---:|---:|---|
| 无噪声，8192 RE，64×128 | −11.298 | −13.017 | 本场景改善1.72 dB |
| 无噪声，4096 RE，64×64 | −4.515 | −5.322 | 改善0.81 dB，仍未达到−10 dB |
| 无噪声，4096 RE，128×32 | −2.364 | −2.390 | 近乎持平 |
| 无噪声，4096 RE，128×32交错 | −5.007 | −6.108 | 改善1.10 dB，仍未达到−10 dB |
| 无噪声，128 RE，16×8 | −0.038 | −0.041 | 完整CSI补全仍失败 |
| 标定20 dB，8192 RE，64×128 | −10.801 | −7.724 | A1退步3.08 dB |
| 标定20 dB，4096 RE，64×64 | −4.347 | −3.206 | A1退步1.14 dB |

两个带噪设置在该场景的实际理论白化SNR为20.376/20.380 dB，噪声实现SNR为20.379/20.376 dB。其噪声方差均由全部2048训练场景的平均功率除以100得到，没有按验证真值改噪声。不同场景的功率不同，因此实际SNR不要求恰好20 dB。

这些现象支持继续做冻结先验的融合诊断，尚不支持A1稳定优于原方法；尤其不能以无噪声收益抵消带噪退化。带噪退化可能涉及标量近似、离线扰动与在线状态的差异、递推方式等，当前未定位唯一原因。

人工完整CSI去噪也有明显的时间尺度差异：验证场景0在t100的NMSE为+9.340 dB、相关性0.044；t50为−10.680 dB、t1为−37.500 dB。低扰动去噪有效不能代表高扰动阶段先验已充分，也不能单据该表区分网络能力与压缩恢复失败。这里只记录一个场景的诊断信号。

## 3. 正式验证与继续条件

默认新前缀`d041_fusion_probe_20261016_v1`尚未运行。标量方差用256训练场景、完整100步标定；先在32验证场景上调原方法六个引导值，再在另外64验证场景上冻结筛选。带噪参考功率仍用全部2048训练场景。预计5376条最终指标、全部有限时426624条反向轨迹。
