## 1. 预算与对照

固定300 GHz、30 GHz/128频点、单发射端、8×160米制接收DMA、配对三径、无吸收和零物理观测噪声。每个RE输出8个复观测，目标始终是完整163840维复CSI。同一宽带先验用于全部采集协议。

| 导频RE | 主组：J配置使用次数×每配置Kp频点 | 含对照的算子数 |
|---:|---|---:|
| 128 | 1×128、2×64、4×32、8×16、16×8 | 26，包含原循环库13组 |
| 512 | 4×128、8×64、16×32、32×16、64×8 | 14 |
| 1024 | 8×128、16×64、32×32、64×16、128×8 | 14 |
| 2048 | 16×128、32×64、64×32、128×16 | 11 |
| 4096 | 32×128、64×64、128×32 | 8 |
| 8192 | 64×128、128×64 | 5 |
| 非等资源参照 | 全频数字、全频DMA J192 | 2 |

共24个主设置、80个算子，每个预算独立保存。所有新主组使用现有D-041的192个随机谐振状态库前缀，不把16个旧图案重复使用称为新增状态。旧循环库13组在新的128 RE运行中逐组重算，原结果不覆盖。

对每个J×Kp设置：

1. **不同状态主组**：前J个不同状态，每个状态使用相同的规则全带Kp频点，沿用`full_band_pilot_indices`。
2. **同状态重复**：J>1时保持首个状态，使用完全相同的时隙、频点、RE和单位RE能量；只有1个不同状态，0次切换。
3. **等RE交错覆盖**：Kp<128时保持相同J个不同状态，第j个状态使用`j mod (128/Kp) + (128/Kp)×[0,…,Kp−1]`。全部128频点各观测R/128次，总RE和配置使用次数不变。

J1不重复计算相同状态控制；Kp128不重复计算与主组相同的交错控制。不同状态组实际切换J−1次，保护开销每次0.25符号。J是配置使用次数，不同状态数和切换另存。静态信道覆盖整个训练窗口，尚未验证移动场景可容纳这些时隙。

同预算组的RE和总发射能量相等，时隙和切换可能不同。跨预算固定单位RE能量，总能量随预算增加；无噪声首轮不据此解释带噪能量收益。数字/J192参照不参与等资源排名。

## 2. 计算、选参与冻结

每个算子都计算`clean_ddpm`、同观测`pinv_ls`、`oracle_geometry_ls`。最后一项读取额外真实路径几何，只是结构参照。三个估计器读取相同观测，不新增全局LMMSE、SURE或非规则选频。

物理噪声为0；1e−8/1e−10仍是数值似然复方差，每场景取较差CSI NMSE后在线性域求均值。观测功率继续遍历全部2048个训练场景标定，不读取待评价真值作尺度修正。初始化和场景配对规则沿用D-041。

每算子/数值方差在32验证场景上从[0.5,1,2,4]选引导，保存后才评价对应最终端点。全部7个验证块完成后生成汇总冻结记录，再启动7个测试块。测试全部预声明算子，读取各自验证引导；不从测试重选预算、配置或中间轨迹。

资源工作点预声明为：共同随机库主组中，至少95%验证场景的最坏数值方差NMSE≤−10 dB；满足者按RE最少、再按训练符号最少选择。没有合格项则保留空值。原0.1 dB数值敏感性单独标记，不能以恢复通过替代数值稳定性通过。原“接近J192”配置结论仍在旧扫描中，本轮不修改它。

测试使用此前100个场景，必须称复用测试，不能称新独立测试。正式预期14个评价运行、63360条最终指标、21120个恢复案例及2133120条VP轨迹状态。轨迹包含初态t100及t0，只有t0用于最终指标和选参。

## 3. 运行命令

服务器已有`thz_dma`环境和`d041_noabs_20261013_v2_wb_data/clean`，无需安装、下载输入或训练。默认单GPU运行；用`CUDA_VISIBLE_DEVICES`选择空闲物理卡，进程内部仍写`cuda:0`。新运行前缀不得与已有记录相同。

```bash
cd /home/lsy/THz_DMA
conda activate thz_dma
export CUDA_VISIBLE_DEVICES=0
export BUDGET_PREFIX=d041_budget_sweep_20261015_v1
export BUDGET_SOURCE=d041_noabs_20261013_v2
export BUDGET_DEVICE=cuda:0
export BUDGET_SMOKE=0
export BUDGET_RESUME=0
mkdir -p logs
set -o pipefail
bash scripts/run_d041_budget_linux.sh all 2>&1 | tee "logs/${BUDGET_PREFIX}.log"
```

`all`依次执行7个validation、验证汇总冻结、7个test、测试汇总。也可先运行`validation`，完成后另行运行`test`；测试入口先核对验证汇总及其输入哈希，不会略过验证。

中断后保留同一前缀、来源和设备，用以下命令续跑。源码、配置、数据/模型依赖及冻结记录必须与启动时相同；已完成块经核对后跳过，未完成块逐案例恢复。不要在运行中修改源码或改用另一套输入。

```bash
export BUDGET_RESUME=1
bash scripts/run_d041_budget_linux.sh all 2>&1 | tee -a "logs/${BUDGET_PREFIX}.log"
```

单个预算的标准入口例子，适用于单独补跑尚未创建的块；如需续跑加`--resume`。测试前仍应完成全部验证和验证汇总：

每个运行保存完整解析配置、环境、源码ZIP与哈希、硬件状态/实际选频、SVD谱与秩、全部训练样本的白化观测功率、验证引导及冻结来源、逐案例JSON、最终指标和恢复轨迹。
